核心机制

每张卡，都能指回原文那一句

牌组里存的不只是问答，还存着这段问答从哪一页、哪一行来。抽取时每个字段都要过逐字校验——引用对不上，卡就编译不出来。

工作方式

两条流程，一条建组，一条派生

从一份资料做出新牌组，或者从已发布的牌组派生出填空、选择、对比题。两条都走同一套校验和同一套退出码。

  • 入口统一：PDF / DOCX / TXT / HTML·URL / EPUB 都先 ingest 成带定位的 unit，再往下走同一条链路。
  • 只在一个地方分叉：编号点占比 ≥ 30% 且段落够短才机械出卡，否则一律逐条写 plan.json。散文、讲义禁止走 *-points 适配器。
  • 每步都有闸门：check、verify 失败即 exit 1，不写盘、不打包；抽样是最后一道人工闸。

回退抽样自答答错率高 → 回到第 3 步改卡，不带着问题发布。

  • 源牌组只读：派生过程只读源卡，不改源牌组一个字，产出一副新的独立牌组。
  • 不二次派生：派生出的卡带 derived:* 标签，不会再被当成源卡参与派生。
  • 人工复核不能省：derive review 生成单文件离线 HTML，可标「通过 / 可疑 / 错误」并导出 review-marks.json。

回退校验不过 → 回到第 1 步重新出 plan，源牌组始终不动。

上手

一条命令链，从文档到 .apkg

需要 Python 3.12。下面的最小链路可以直接复制；完整的参数与闸门见仓库 README。

终端 
python3 -m ankicards ingest 手册.pdf
python3 scripts/precheck.py --ingest .work/ingest/*.json
# agent 只写 plan.json：每卡带逐字 quote，看过的段落记 skipped
python3 -m ankicards plan check   plan.json --ingest .work/ingest/*.json
python3 -m ankicards plan compile plan.json --out data/新牌组 --ingest .work/ingest/*.json
python3 -m ankicards build  data/新牌组 --pdf 手册.pdf --ingest .work/ingest/*.json --out dist/新牌组.apkg
python3 -m ankicards verify dist/新牌组.apkg

退出码约定：0 成功；1 数据或闸门失败；2 用法或环境错误（坏 JSON、加密 PDF、缺 --ingest、拒绝覆盖等）。

质量控制

九条确定性规则，三道人工闸

能在代码里判死的就不靠人看；判不死的，明确交给人。

  • 答案过短
  • 截断
  • 交叉引用
  • 版面词当正面
  • 正反重复
  • 过长
  • 表头当数据
  • 一卡多点
  • 结尾不完整

严格模式

derive plan --strict 额外做题干实体锚定、碎片流跳过。公共牌组默认关闭以免误杀，私有文档建议打开。

人工复核

derive review 产出离线 HTML，逐张标「通过 / 可疑 / 错误」后再编译。

抽样自答

发布前遮住背面自答 10 张；散文类还要能指回原文具体一句。

常见问题

它做不到什么

扫描件、截图、图片型 PDF 能做吗？

不能。这类文件没有文本层，项目不做 OCR。

小说、散文可以一键全自动出卡吗？

不行，需要人判断哪些段落值得做成卡。工具的承诺是「不撒谎」而不是「不劳而获」：--ingest 只证明定位存在，不证明内容正确。

派生会改我原来的牌组吗？

不会。派生流程对源牌组只读，产出的是一副新的独立牌组。

重复导入会产生重复卡片吗？

同一 guid 的卡会覆盖更新，不会重复。跨大版本升级时，模型或 guid 变化的情况需要先删旧根牌组，详见对应 Release 的升级说明。

需要联网吗？

不需要。除了抓取 URL 那一步，其余全在本地运行。
