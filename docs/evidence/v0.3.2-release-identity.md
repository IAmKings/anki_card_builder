- 日期：2026-11-09
- 修复前 HEAD：`5f1f52d`（tag `v0.3.1`）
- 修复后版本：`0.3.2`（P0-only）
- 范围：仅公开数据 `data/Android/`、`data/MQTT/`；不含任何机密材料

## 1. 基线：v0.3.1 Release 资产 = 旧 output 包

用 GitHub API 下载 `v0.3.1` 的资产后计算：

| 资产 | 大小 | sha256 |
|------|------|--------|
| `Android.apkg` | 1,396,954 | `fbacdb9e1497d9df8aa7bbe5018a561d7517207c16dd34a97ba78dab159d59c6` |
| `MQTT.apkg` | 258,266 | `65c59e9930c1fdb35100ae73a7ef55f47a44a4d6d1e7a91d5d916c8eeec2d620` |

两个 sha256 与仓库 `output/Android面试卡组.apkg`、`output/MQTT协议卡组.apkg` 完全相同，
说明 v0.3.1 只是把历史 `output/` 文件上传，而不是在 tag 上从源码构建。

## 2. 用当前 HEAD 重建后的身份差异

命令：

```bash
python3 -m ankicards import data/Android --adapter android-md \
  --out /tmp/p0-new-android --name "Android面试"
python3 -m ankicards build /tmp/p0-new-android --out /tmp/p0-baseline/new-android.apkg

python3 -m ankicards import data/MQTT --adapter mqtt-md \
  --out /tmp/p0-new-mqtt --name "MQTT协议"
python3 -m ankicards build /tmp/p0-new-mqtt --out /tmp/p0-baseline/new-mqtt.apkg

python3 scripts/apkg_identity.py /tmp/p0-baseline/old-android.apkg /tmp/p0-baseline/new-android.apkg
python3 scripts/apkg_identity.py /tmp/p0-baseline/old-mqtt.apkg /tmp/p0-baseline/new-mqtt.apkg
```

| 指标 | 旧 Android | 新 Android | 旧 MQTT | 新 MQTT |
|------|-----------:|-----------:|--------:|--------:|
| notes | 1270 | 1270 | 200 | 200 |
| cards | 1270 | 1270 | 200 | 200 |
| guid 交集 | — | **0 / 1270** | — | **0 / 200** |
| 模型字段数 | 4 | 5 | 4 | 5 |
| 模型名 | `Android 面试 Q&A` | `Android面试 · 问答` | `MQTT Q&A` | `MQTT协议 · 问答` |
| 模型 id | `1607392319` | `1629099444` | `1907392319` | `1658860862` |
| 牌组 id | `2060286443` 等 | `1711842422` 等 | `3860191135` | `1705832265` 等 |

结论：两套包没有任何共同 guid，模型字段从 4 个变 5 个，模型 id、牌组 id 全部不同。
Anki 会把新包识别为全新卡组，**覆盖导入必然产生重复卡片**，因此 v0.3.2 Release notes
必须要求先删除旧根牌组 `Android面试`、`MQTT协议`（含子牌组）。

## 3. 修复后：重建、校验与 golden

```bash
python3 scripts/build_public_decks.py --out dist --check-golden
```

结果：

| 卡组 | 文件 | notes | cards | guids | guid_sha256 前缀 |
|------|------|------:|------:|------:|------------------|
| Android | `dist/Android.apkg` | 1270 | 1270 | 1270 | `91ff8307b6e9a92e` |
| MQTT | `dist/MQTT.apkg` | 200 | 200 | 200 | `f2c6233034427a5f` |

`python3 -m ankicards verify` 对两个包均返回“结构检查通过”。重建后的参考包已写回：

| 文件 | 大小 | sha256 |
|------|------|--------|
| `output/Android面试卡组.apkg` | 1,417,434 | `b1f79b31a312ce088a0f602b01f7d3a86b0388165876cacd4d4ff8d6abecbc55` |
| `output/MQTT协议卡组.apkg` | 286,938 | `9a9cf14a0a7f35b8e06845a3dc41750693729c9af5eeb2b3a9b9bb101570f2c6` |

> apkg 的字节级 sha 会因 genanki 打包时间戳变化；发布校验用的是 guid/模型/牌组身份，
> 不是字节 sha。上表是本机参考构建的 sha，用于人工核对，不写死进 Release notes。

## 4. 新增的保护

- `scripts/build_public_decks.py`：只从 `data/Android`、`data/MQTT` 构建，构建后自动 `verify`，再比对 `tests/golden/public_decks.json`。
- `scripts/apkg_identity.py`：读取任意 apkg 的 guid 集合、模型字段/模型 id、牌组名/牌组 id，并打印交集。
- `tests/test_release_workflow.py`：锁住 release workflow 必须构建、必须 `--check-golden`、只上传 `dist/Android.apkg`/`dist/MQTT.apkg`、必须带迁移说明与已知限制。
- `.github/workflows/release.yml`：`v*` tag 上执行 `import → build → verify → --check-golden` 后上传；不再 `find output`。
- `.github/workflows/verify.yml` 的 `public-decks` job：每次 push/PR 重建并校验 golden。

## 5. 明确的已知限制（v0.3.2 不修）

- `--ingest` 只验证定位是否存在，不证明“与某个 `--pdf/--docx/--txt/--html` 同源”；跨文档/机密材料的溯源承诺留到 v0.3.3。
- 未包含 Anki/AnkiDroid 真机导入；A8b 真机验收在 v0.3.3 门槛中执行。
- 本证据不包含任何机密 PDF、卡片或截图。
