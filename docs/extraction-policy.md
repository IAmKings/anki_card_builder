# 抽取策略：什么能自动抽，什么必须逐条确认

本文件规定「文档 → 卡片」这一步的判定与红线。它约束的是**人和 agent 的作业方式**，不是代码契约；代码契约见 `ankicards/schema.py`。

结论先写在这里：

> 适配器只适合「知识点已经被编号点排版标出来」的资料。散文、手册、讲义必须走 `ingest` → 写 `plan.json`（每条带逐字 `quote`）→ `plan compile`，且每条都要能指回原文。任何生成式流程（含 LLM）都不得直接产出 `cards/*.json`，只能写 plan。

## 1. 三类文档形态

| 形态 | 判据（满足任意两条即可判） | 路径 |
|---|---|---|
| 结构化题库 | 有成对的题干/答案；或有“标题 + `1. **关键词**：解释`”的稳定版式；编号点密度高且每点自带一句解释 | `import --adapter <name>` |
| 手册 / 讲义 / 散文 | 成段叙述；编号点只是排版手段，正文仍靠段落展开；大量“因为/因此/通常/注意/前提是” | `ingest` → `plan.json` → `plan compile` |
| 小说 / 电子书 | 叙事文本，无知识点标记；同一事实分散在多章 | `ingest` → `plan.json`；单独 profile，不在本文件覆盖范围 |

判不准时**按最保守的那一类处理**。误判成题库的代价是产出一批看着通顺、实际不可背的卡，而这些卡能通过全部现有校验。

## 2. 为什么适配器只认编号点

`txt-points` / `docx-points` / `web-points` 的实现是**单行正则**：匹配到 `1. **关键词**：解释` 就切一张卡，关键词短或含“含义/概念/定义”时把正面拼成“什么是 X？”。它不读上下文，因此：

- 编号点后面**换行续写的正文**不在同一行 → 丢失；
- 编号点下的**子项**（`-`、`a)`）不在匹配式里 → 丢失；
- 整段只有“见第 4 节。”这种交叉引用时，它仍然出卡；
- 步骤类编号（“1. 准备环境”）会被当成概念，产出“什么是环境准备？”。

更关键的一点：这些丢失**不会让校验失败**。`check` 只验证字段、非空、定位存在、定位文本非空；它不知道答案少了下半句。

实测（4 行样本：一个标题 + 4 个编号点，含续行、两行子项、一处交叉引用）：

| 产出 | 问题 |
|---|---|
| `什么是环境准备？` | 步骤当概念；两条子项丢失 |
| `什么是启动服务？` | 答案在“端口 8080；”处截断，续行丢失 |
| `什么是日志位置？` → `见第 4 节。` | 交叉引用当答案 |
| `什么是幂等？` | 正常 |

同一批卡片再跑 `check --txt --ingest`：**校验通过，退出码 0**。

## 3. 散文 / 手册的正确做法

1. `ingest` 出可寻址文本（`line:N` / `para:N` / `block:N`），先看 `unit_count` 与 warnings。
2. 逐条写卡：一条只承载一个可独立作答的知识点；答案必须是原文该处的完整语义单元，不能停在分号。
3. 每条卡都要能回答“依据是原文哪一句”。指不出来就不写这张卡。
4. 覆盖不了的段落**明确记账**（见 §5），不要用造卡来凑覆盖率。
5. 交付前抽样自答（见 §6）。

判断“值不值得背”没有外部标准可查，所以这一步的产物必须**可被人复核**：卡面 + 依据 + 未覆盖清单，三者一起看。不要只交付卡面。

## 4. 硬性红线

1. **散文 / 手册 / 讲义禁止走 `*-points` 适配器。**
2. **agent / LLM 不得直接写 `cards/*.json`。** 归纳、改写、总结只能落在可审阅的中间产物上（`plan.json`，规划中，见 §8），再由确定性步骤编译成卡。
3. **已发布牌组不重跑抽取。** 身份由 `q`/`a` 文本决定（`identity_seed`），重写文本在 Anki 里就是新卡。要改就改卡面文本。
4. **不以“校验通过”作为内容正确的证据。** `check` / `verify` 全绿只说明结构合法。

## 5. 未覆盖记账（已实现）

覆盖率的意义是“我确实看过这一段，并决定不出卡”，不是“这一段出了卡”。

适配器会把每个没变成卡片的源单元记进 `<deck>/import-report.json` 的 `skipped` 数组；`plan.json` 的 `skipped` 则是人/agent 在读过之后给出的理由。两边共同写进编译产物的 `skipped_by_reason`。`reason` 是封闭枚举，不要随手发明新值：

适配器（机械原因，`ankicards/adapters.py` 的 `SKIP_REASONS`）：

| reason | 含义 |
|---|---|
| `blank` | 空行 / 空块 |
| `heading` | 标题，无可背内容 |
| `not_point` | 不是编号点（散文、过渡段） |
| `continuation` | 续行/子项，没有独立成点 |
| `table_header` | 表头当数据 |
| `duplicate_input` | 源文本内部重复 |

plan（读过之后的判断，`ankicards/plan.py` 的 `PLAN_SKIP_REASONS`，在上面六个之外追加）：

| reason | 含义 |
|---|---|
| `step_not_concept` | 步骤/操作流程，不适合做记忆卡 |
| `cross_reference` | 只有“见第 N 节”之类的指路 |
| `merged_into` | 已并入另一张卡，`note` 写目标定位 |
| `low_value` | 读懂了，但不值得背 |
| `out_of_scope` | 明确不在本次范围 |
| `unreadable` | 原文残缺/排版坏了 |

## 6. 交付前抽样

- 随机抽 10 张（不足 10 张则全抽）。
- **遮住背面，先只看正面自答**，再翻面对照。
- 记录三类结果：答对 / 答不出 / 答错。
  - 答不出 → 卡面问法不可背，改问法或改卡。
  - 答错 → 抽错了知识点，或答案本身有歧义，退回重写。
- 记录校对基准：源文件 hash 或 git commit，以及 ingest 的 `source_sha256`。
- 不要只报“通过率”。通过率不能证明内容对，只能证明抽样者手松。

## 7. 已知失败模式

| 现象 | 成因 | 处理 |
|---|---|---|
| 答案在分号/逗号处截断 | 单行切点，续行丢失 | `import --ingest` 按组出卡（P2 已实现）；或改走逐条写卡 |
| 子项消失 | 子项不在正则里 | `import --ingest` 把缩进子项并进同组答案（P2 已实现）；或改走逐条写卡 |
| “什么是第一步？” | 步骤当概念 | 该段记 `step_not_concept` |
| 答案只有“见第 4 节。” | 交叉引用当正文 | 记 `cross_reference`，不出卡 |
| 一张卡塞了三个知识点 | 编号点下的并列项被并进答案 | 拆卡，或只保留一个可独立作答的点 |
| 表头变成答案 | 表头词表命中 | 记 `table_header` |
| 同一知识点两张卡 | 跨章节重复 | 合并，记 `merged_into` |
| 引用被润色过 | 归纳时顺手改写 | `plan check` E1 拦：quote 必须是逐字子串 |
| 卡面数字原文没有 | 模型补数或换算 | `plan check` E2 拦：答案里的数字必须出现在 quote 里；问题里的编号（「案例 2」「第 4 节」）不算 |
| 一整段被跳过却说不清原因 | 没真读，或读了没记账 | `plan check --min-coverage` + 未覆盖分组清单 |

## 8. 状态与后续

已落地：

- **P1**：`ankicards/quality.py` 的 Q1–Q9 确定性规则（默认只报告，不阻断）；`import` 写 `import-report.json`，含 `skipped`（未出卡理由）与 `findings`（规则命中）；`import --strict` 让 error 级问题直接失败且不写牌组。
- **P3**：`plan.json` 契约落地（`ankicards/plan.py`）。每张卡必须带逐字 `quote`，校验规则 E1–E7：quote 是定位文本的逐字子串（空白归一）、答案里的数字必须出现在 quote 里（问题里的数字只提示）、quote 长度 8–300、定位存在且非空、未出卡理由属于枚举、任意两条目区间不得相交（**P3 当时如此；E5 后来放宽为「同一定位只要 quote 不重叠即可多卡」**）、分组覆盖率可选下限（`--min-coverage`）；另有「卡面出现原文没有的 ASCII 专名」warning。`plan check` 只读；`plan compile` 校验通过才写牌组并复用 `write_deck`（含 `import-report.json`）；`plan diff` 对比 plan 与现有牌组会新增/删除/改动哪些卡（按归一后的卡面文本比对）。`quote` 不进卡片字段，只留在 plan 里作为审计记录。
- **P4**：可选卡身份 `key`（12 位小写十六进制，`plan compile --with-key` 生成，只用于新牌组）。有 key 的卡按 `(key)` 定 guid：改措辞不会在 Anki 里变成新卡；同一页/同一段内新增卡会改变后续 `seq`，从而改变 key（这是显式代价）。
- **P6**：EPUB ingest（`chapter:C/p:M`，章节顺序取自 OPF spine，每个 `<p>` 独立成组）+ `plan --profile novel`（quote 上限 800 字、未出卡理由追加 `plot_summary`/`spoiler`/`character_note`）与 `--profile essay`（散文/随笔：quote 上限 800 字、理由追加 `anecdote`/`style_note`/`background`）。两者都仍按“逐段引用 + 人抽样”验收，不做情节或主旨归纳。
- **P2**：`ingest` 产出 `groups`（编号点 + 缩进子项 + 没说完的续行归成一组），并把组区间（如 `line:3-7`）注册为合法定位；`import --ingest <清单>` 让 `txt-points`/`docx-points`/`web-points` 按组取点，答案并入组内其余文本，`source` 写区间；`schema.parse_locator` 校验区间次序（起点不得大于终点），闸门要求整个区间出现在 ingest 产物里。不加 `--ingest` 时行为与 P1 完全一致。
- MOBI/AZW 没有 ingest 路径（`BOOKMOBI`/PalmDOC 未实现）；需要时先用 Calibre `ebook-convert` 转成 EPUB，转换步骤不进本仓库。
- 注意 Q4 只认 `第一步/步骤/注意/说明/示例/小结/总结/提示` 这类显式词；“环境准备”这种步骤标题抓不到，靠 `skipped` 里的 `continuation` 计数和人的复核。走 `--ingest` 分组路径后，续行/子项被并进答案，`continuation` 不再产生；散文段则记为 `not_point`。

仍未实现：

- P5 离线 LLM 抽取器（按用户决定搁置：当前最大问题不是“谁来抽”，而是抽取契约本身）。
- P3 只解决「转述有没有原文依据」；它不判断「这个知识点值不值得背」——那仍是人的抽样与判断（§6）。
- 本文件随各阶段更新；新增 `reason` 或 `plan` 字段时同步改这里，不要只改代码。

## 9. 真实讲义验收记录（2026-11-10）

样本：仓库内一份 1572 行的性能优化讲义（Markdown，转成 txt 后 ingest；1572 个行单元、575 个分组）。人工/agent 按组原文写了 7 张卡 + 6 条未出卡记录，走 `plan check` → `plan compile` → `check --txt --ingest`。

误报（规则过严，已修）：

- **E2 把问题里的编号当卡面数字**：问题写「案例 2：…」「案例 13（…）」时，`2`/`13` 不在 quote 里，整份 plan 报两条 error，而卡面没有任何编造事实。已改为：数字只查答案（cloze 查 text/extra），问题里的数字降为 warning，并豁免「案例/第/图/表/章/节/页/步/项 + 数字」这类编号写法。

卡住的地方（规则没错，但真实文本上代价高，待决策）：

- **quote 必须带源文本的 Markdown 标记**：`**加粗**`、`> 引用`、代码围栏都在行文本里，从渲染视图复制必然 E1 报错。工作流上必须从 ingest 文本取引用；是否给 Markdown 输入做「去行内标记的文本层」尚未决定。
- **区间定位只能引用单元或 ingest 已合并的组**：`line:1447-1454` 这种跨行区间会报「定位不在 ingest 产物中」。排版图/代码围栏的每一行各自成组，想整段引用做一张卡做不到，只能逐行出卡或改分组规则。
- **覆盖率在案例型讲义上不可用**：575 组只覆盖 13 组（2%）；`--min-coverage 0.5` 直接失败。这类文档「看过」不等于「每组都该出卡」，覆盖率更适合规整文档，或按章节/主题统计。
- ~~**同一段只能出一张卡**~~：**已解决**。E5 早期要求条目区间不相交；现在同一定位只要 `quote`
  不重叠就可以出多张卡，「是什么」和「什么时候用」可以各占一句、互不覆盖。
- **数字校验只比 digits**：`800ms` 写成 `0.8 秒` 会被拦（0.8 不在 quote），但写成「八百毫秒」或漏掉单位不会被拦；中文数字不在校验范围内。
- 空白归一工作正常：手打箱线图行、与原文空格数不同，仍通过 E1。

## 10. 卡型与密度：一次实测量（2026-11-10）

密度不能靠感觉定。用同一本散文集的前三个内容章（chapter 6 / 7 / 9，共 20,474 字）按
「每篇 3–5 张」写了 14 张卡，再反推全书。

| 项目 | 数值 |
|---|---|
| 三章字数 | 20,474 |
| 卡片数 | 14（claim 10、phrase 4） |
| 实测密度 | 1,462 字/卡 |
| 全书 74,300 字外推 | 约 51 张 |
| 按每篇 3 张（13 篇） | 39 张 |
| 按每篇 5 张 | 65 张 |
| 按每篇 8 张 | 104 张 |

对照组（知识型文档，公开测试牌组）：

| 牌组 | 源文档 | 卡片 | 密度 |
|---|---|---|---|
| Android | 456,494 字 | 1,270 | 359 字/卡 |
| MQTT | 8,565 字 | 200 | 43 字/卡 |

结论：

1. **同一套工具，两种密度**。知识型文档一条信息点一张卡（MQTT 43 字/卡）；散文随笔
   1,400 字/卡上下，差 4–34 倍。密度是文体属性，不该用统一阈值卡。
2. **散文类按篇配额，不按字数配额**。每篇 3–5 张 → 全书 40–70 张；早期估算的
   「120–200 张」偏高，已被实测推翻。
3. **卡型配额要分开给**。这次 14 张里 `claim` 10 张、`phrase` 4 张，`style` 和 `fact`
   一张都没有——写卡时观点会吃掉全部名额。若确实要文风卡，必须单独规定「每篇至少
   1 张 style」，否则它永远不会出现。
4. **同段多卡是必要的**。这本书常见「前半观点、后半金句」的段落；放开 quote 不重叠的
   同段多卡后，一段可以各取一句，密度才不被规则人为压低。

## 10.1 密度闸门（P8，2026-11-10）

§10 的密度结论已实现为可选检查：`plan check --density {manual,novel,essay}`
（或 `--density-min/--density-max` 覆盖）。

- 分子是**条目实际覆盖到的原文**（按 group 去重；PDF 按页去重），不是卡片自己那一小段——
  否则一段 70 字出两张卡会被算成 35 字/张，永远误报「太密」。
- 分母是卡数。散文实测 74,002 字 / 88 张 = **844 字/张**，落在 essay 带内。
- 口径：`manual` 200–700、`novel` 400–1200、`essay` 600–1600。
- 只给 warning，不拦编译：密度是启发式，硬拦会逼人硬拆或凑卡。
- 卡型配额：`essay` 出现 `fact` → 提示（这类文本没有可检验事实）；`manual` 的 `fact`
  占比低于 30% → 提示（考点型资料应以可核对的事实为主）。

## 10.2 跨格式交叉校验（2026-11-10）

同一本书常有 EPUB/PDF/TXT 多份，定位体系互不相同（`chapter:C/p:M` / `page:N` / `line:N`），
但正文应当一致。`plan check --also <另一份 ingest>`（可重复）把每张卡的 `quote` 拿到第二份
里逐字重找：

- **命中**：两份内容一致，说明抽取没有改写原文。
- **找不到**：两份文本不一致，或被格式改写（引号、全半角、断字）。这是 content 层的问题，
  不是定位层的问题。
- **能命中但要跨单元拼接**：报告「跨单元 N」。典型是 PDF 换页把一句话切断——内容没丢，
  但该格式的定位无法单点溯源，需要 `page:N-M`。

实测：散文集 88 张卡，在 PDF 里 88/88 命中（3 张需跨页拼接），在 TXT 里 88/88 命中。
同格式重复给 `--also` 会提示「意义有限」——换另一种格式才有校验价值。

## 10.3 小说防剧透（2026-11-11）

`--profile novel` 会自动跑三项检查。前两项是确定性信号，第三项靠声明：

| 信号 | 级别 | 判据 | 为什么是这个粒度 |
|---|---|---|---|
| 复制后文整句 | warning | 卡面含长度 ≥6 的中文连续片段，且该片段在全书首次出现晚于卡片定位 | 够长才稀有；散文体实测 88 张卡 0 误报 |
| 后文拉丁名 | warning | 卡面出现 `[A-Z][a-z]{2,}` 形式的词，首次出现晚于卡片定位 | 拉丁名大小写本身就是信号 |
| 声明的实体提前出现 | error | `plan.entities` 里 `{name, locator}`，卡面在 locator 之前提到它 | 中文人名无法可靠自动识别，只能声明 |

**为什么不做中文人名自动识别**：先试过「中文 2–3-gram + 首次出现位置」，同一份散文集
88 张卡里 52–74 张被标（「作者」「來之」「一件事」都会中），噪声大到无法使用。改成上面
两条后误报 0，代价是漏报：没有声明实体时，中文人物名提前登场抓不到。这是有意选择的
「宁可漏，不可误报」——猜名会把整页标红，用户很快就学会无视 warning。

误报的两个来源值得记：① 引文与卡面共用同一句时，`quote` 里的片段不算泄漏（已排除）；
② 同一件事在后文第一次被**逐字**写出、前文只是转述，也会被判为提前引用（保守方向，
记 warning 而非 error）。

## 10.4 增量编译（2026-11-11）

已发布的牌组不能靠「重写整个目录」来更新——重写会换 guid，Anki 里就变成删卡再建卡，
复习记录全丢。`plan compile --incremental` 的做法：

- plan 里出现的卡按 `key` 落到已有牌组上（同 key = 同一张卡，改措辞不产生新卡）；
- `"retired": ["<key>"]` 里列出的卡从牌组移除；
- plan 没提到的旧卡**原样保留**——plan 只管这次读到的东西，不代表要删掉没读的；
- 旧卡没有 key 时只能按内容身份对齐，且无法被 `retired` 删除，会给 warning 提示。

**不自动对账**：Anki 侧删了一张卡，本地无从得知；工具不做「用数据库反推」的重活，也不猜。
要下架就在 `retired` 里写 key。这是有意把「删除」变成显式操作——自动对齐一旦猜错，
就是静默丢卡。

plan 里没写 key 时，增量编译用与 `--with-key` 相同的推导（牌组名 + 定位 + 同定位序号）。
所以前提是牌组名没改、定位没变；改过 deck 名的牌组不要用增量，直接重建并接受新身份。

实测：散文集 88 张卡增量编译 → 「保留 0 新增 0 替换 88 下架 0」，`check --epub` 通过。

## 11. 跨页段落（P7a，2026-11-10）

PDF 的定位单位是页，但排版上的段落会跨页。以前只能按单页引用，跨页的句子要么被
截断（丢后半句），要么整张卡作废。

- `plan.json` 的 PDF 定位支持区间 `page:N-M`，`quote` 可取两页拼接后的文本（比较时
  忽略空白，换页处的换行不影响逐字校验）。
- `plan compile` 把区间写成 `pages: [N, M]`；背面同时渲染两页，不会只显示半句话。
- ingest 清单新增 `page_spans`：对每对相邻页，若上一页非空且最后一个字符不是句末
  标点、下一页也非空，就记一条 `{"locator": "page:N-N+1", "pages": [N, N+1]}`。这只是
  **提示**，不代表一定续写；怎么用仍由写卡的人判断。
- 实测（200 页、77,378 字）：检测到 46 对续页；跨 `page:190-191` 的 241 字 quote 通过
  校验并成功编译，同一 quote 用 `page:190` 会被拦下。
- 仍未解决：`crops.json` 的裁图只支持单页（`page` + `rect`），跨页段落要裁图仍需手工；
  同一段跨三页以上目前要写 `page:N-N+2`，没有额外提示。

## 12. 可卡性预检：五个指标定口径（2026-11-10）

形态判定回答「能不能自动抽」，但「该抽什么卡型、多少张」还要看文本的客观特征。
`ingest` 之后先算下面五个指标，再决定卡型组合与密度带——这是把「读完才发现错配」
提前到开工前的 30 秒。

| 指标 | 算法 | 阈值 | 指向的决策 |
|---|---|---|---|
| 编号点占比 | `^\d+[.、]` 开头的非空单元 / 非空单元 | >30% 可走 `*-points`；<10% 禁止 | 是否走自动适配器 |
| 数字句占比 | 含 `\d` 的句子 / 总句子 | <3% 不出 `fact`；>30% `fact` 可为主力 | 卡型组合 |
| 平均段长 | 非空单元字数均值（同时看中位数、>300 字占比） | >300 字占比 >20% → 长引用风险，优先 EPUB | 定位粒度、跨页风险 |
| 引号密度 | （`「` + `“`）数 / 非空单元 | >0.8 个/段 → 对话/引语型，出情节卡或金句 | `phrase`/`fact` 取舍 |
| 表格行占比 | `table:` 定位行 / 总单元 | >20% → 词表型资料，`fact` 密度可拉到极高 | 是否按表出卡 |

两个实测样本（同一套算法）：

| 样本 | 非空单元 | 编号点 | 数字句 | 平均段长 | >300 字 | 口径结论 |
|---|---|---|---|---|---|---|
| 散文集《一千七百種靠近》EPUB | 1,060 | 0.3% | **0.6%** | 70 字（中位 36） | 1.4% | 不出 `fact`；`claim`/`phrase`/`style`；800–1,200 字/张 |
| 技术手册 TXT（性能优化案例） | 1,238 | 0.0% | **52.0%** | 30 字（中位 27） | 0.0% | 以 `fact` 为主力；短段可直接一卡一条 |

两者的数字句占比差 **87 倍**——这就是「同一套工具两种密度」的客观来源，不是写卡人
的手感差异。

可直接复制的算法（只读 ingest 清单，不改仓库）：

```python
import json, re, statistics

d = json.load(open("ingest.json"))
units = [u for u in d["units"] if (u.get("text") or "").strip()]
texts = [u["text"].strip() for u in units]
joined = "\n".join(texts)
sents = [s for s in re.split(r"[。！？!?…]+", joined) if s.strip()]
lens = [len(t) for t in texts]
print("编号点占比", sum(1 for t in texts if re.match(r"^\d+[.、]", t)) / len(texts))
print("数字句占比", sum(1 for s in sents if re.search(r"\d", s)) / max(1, len(sents)))
print("平均段长", statistics.mean(lens), "中位", statistics.median(lens),
      ">300字占比", sum(1 for x in lens if x > 300) / len(lens))
print("引号密度", (joined.count("「") + joined.count("“")) / len(texts))
print("表格行占比", sum(1 for u in d["units"]
      if str(u.get("locator") or u.get("id") or "").startswith("table:")) / len(d["units"]))
```

使用边界：

- 这五个指标只用于**选路与定口径**，不参与 `plan check`。覆盖率仍由 E6 负责，密度是否
  合理仍由人判断（见 §10）。
- 阈值是启发式，不是断言。指标与人工判断冲突时，以人工判断为准，但要说明理由。
- 指标低不代表不能出卡，只代表**不能出那一类卡**：散文数字句 0.6% 就不该有 `fact`，
  但它可以有很好的 `claim` 与 `style`。
